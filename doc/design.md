# 界面设计与前端修改约定

TokenFlow 面向在本机管理编码客户端、模型来源和登录账号的用户。界面沿用现有桌面工具的主题、字体、颜色与紧凑布局；反馈准确、克制，操作进度和结果留在当前上下文中。

## 修改前

1. 新增 UI 或修改前端前，先阅读本文件、根目录 `.impeccable.md`，并查看目标页面及相邻功能的现有效果，理解项目设计理念后再开始。
2. 检查现有功能是否已经组件化，搜索共享组件、样式和调用位置。优先复用已有组件及效果；通用行为在共享组件内维护，不为不同页面再写一套。
3. 将修改范围限定为用户明确提出的部分。其他位置保持原样；未经用户要求，不额外添加特效、提示、框线、发光、模糊或装饰动画。

## 共享反馈

- 消息统一使用 `Notifications`，固定在窗口右下方；侧栏、维修面板或弹窗打开时，通知仍保持右下位置。
- 所有 Thinking 调用复用 `LoadingState` 的同一个居中反馈层，同一时刻只显示一组动画。页面、按钮和弹窗只声明加载状态，不各自在原位显示另一组 Thinking。
- Thinking 层无框线、不拦截鼠标；按用户要求，复用现有 3px 背景高斯模糊，让下方页面及叠加弹窗与动画区分。Thinking 文字使用主题正文色，并始终位于最新打开的弹窗上方。延续现有动画及减少动态效果偏好；已有骨架或弹窗时，不额外显示页面操作的兜底 Thinking。关闭的弹窗不贡献加载状态。
- 弹窗复用 `FlowDialog`；保留原有关闭、键盘和防重复提交行为。

## 本地 Agent 应用模型

- 点击「应用所选模型」并进入实际配置流程时，立即显示操作窗口；安装或默认／快速模型选择继续使用已有前置界面。
- 保留 Claude CLI 与 Claude Desktop 的客户端切换入口。两者选好多个模型并点击「应用所选模型」后，再选择默认模型和快速模型；Claude Desktop 模型列表旁不单设「默认模型」按钮。单模型直接使用该模型。
- Claude Desktop 页面仅展示普通模型列表，不显示默认／快速角色标记、角色用途说明或角色高亮。角色选择和用途说明仅在应用对话中展示；模型不可用状态继续保留。
- 复用 Codex 保留旧对话操作的居中弹窗效果。窗口宽度沿用紧凑弹窗的 440px，高度固定为 360px，较小视口内按可用空间收缩。进度、结果、失败及重启选择在同一个窗口里切换，窗口尺寸和位置保持稳定。
- 配置处理中显示共享 Thinking 和实际阶段；Codex 沿用已有退出、备份、迁移及重新打开阶段。其他客户端只说明正在应用配置，不伪造百分比或完成时间。
- 保存完成后，直接在当前窗口说明结果；支持重启且需要重启时，在同一窗口显示「稍后再说／立即重启」。已自动重新打开的客户端显示完成结果。
- 失败原因和重试留在当前窗口，不再叠加同一操作的 toast 或另一层结果弹窗。关闭窗口后仍可从已有 Agent 标题入口重启。

## 验收

核对右下通知（维修面板开／关）、多个并发加载请求、关闭弹窗的加载状态、慢速配置、配置失败重试、重启成功／失败和 Codex 阶段更新。比较处理前后的窗口坐标与尺寸，并确认只出现一组 Thinking；检查深浅主题和小窗口，区分模拟界面验证与真实客户端验收。
