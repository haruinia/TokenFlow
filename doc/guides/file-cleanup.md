# 文件清理

在侧栏 **文件清理** 点击 **开始扫描**。默认检查当前用户的已知 Agent、应用、开发工具、桌面、下载与应用位置；在 **扫描范围** 添加项目目录，或选择扫描所有可访问磁盘，扩大查找范围。扫描有时间、目录和文件数量限制，未覆盖位置会显示提示。

## 旧应用、安装包与调试产物

- **应用分组与版本**：同一应用按 Info.plist 的标识分组，组内按版本及构建号排序，标出较早版本与同版本副本；安装包按名称系列单独归类。较早版本不等于可删除，同版本副本也不等于整个应用内容相同。
- **版本名称线索**：安装包文件名中的版本号用于同系列比较；保留架构等名称差异。名称不证明实际应用版本、过时或重复。
- **内容相同的安装包**：仅对候选安装包中同系列、同大小的文件进行 SHA-256 比较。默认单文件最多 64 MiB、总读取预算 256 MiB；超限或扫描到时会提示，不能把“没标重复”理解为“没有重复”。普通文档、源码和会话不参与内容比较。
- **本地调试应用**：检查项目 release/dist/out/build/artifacts 等打包目录中的独立应用和安装包，以及 TokenFlow 保留的隐藏安装备份。展示具体应用，不把整个项目或 release 目录一起当垃圾。
- **测试与调试证据**：在有项目标记的目录识别 test-results 的 `.last-run.json`、playwright-report 的 `index.html`、coverage 的覆盖率标记。可能包含截图、录像、trace 和报告，归为“需要确认”。
- **可重建缓存**：补充 Python 字节码、pytest/mypy/Ruff/Vite 缓存、Electron 和 electron-builder 下载缓存。这些工具可能由 AI 或人使用，不能证明文件一定由 AI 生成或已经闲置。

通用 `tmp`、`output`、`screenshots` 目录，版本化源文件和文档、Git 工作树、模型权重、账号凭据、数据库和会话不会因为名称相似或修改较早而被认定为垃圾。

## 风险分类与执行

**可重建缓存**支持手动批量选择；**需要确认**包括安装包、旧应用候选、测试报告、项目依赖和部分备份；**受保护数据**包括会话、配置和共享存储，需核对丢失风险后单独确认。默认不勾选新发现的应用、重复包或调试报告。

已知正在运行的程序，以及当前 TokenFlow 程序本身，会禁用清理。执行前再次查询运行路径，并核对所选路径与文件身份。完整统计的项目会比较文件元数据；未完整统计不阻止选择或清理。进程权限、Linux AppImage 挂载、解释器任务等可能使运行检测不完整，仍需退出相关应用和任务。按路径操作仍存在系统级并发变化窗口，不宣称原子删除安全。

桌面版默认移入系统废纸篓 / 回收站，也可选择永久删除。选好文件后在确认页直接点击“确认永久删除”，无需额外勾选或输入文字。回收失败不会自动转为永久删除。移入废纸篓不等于已释放空间；硬链接、文件系统克隆、稀疏文件和快照也会使文件逻辑大小不同于实际释放空间。

清理只接受本次扫描生成的 ID，不接受任意路径或命令。扫描结果 30 分钟后失效；符号链接路径、目标被替换或已确认发生变化的项目需要重新扫描。因扫描上限、部分文件不可读等原因未完整统计的项目仍可选择并确认清理，大小显示为下限（≥）；实际删除遇到权限或占用问题时逐项报告，不将失败计为成功。浏览器 / 无桌面能力的服务只提供只读扫描。维修助手只能扫描和解释结果，不能替用户确认删除。
