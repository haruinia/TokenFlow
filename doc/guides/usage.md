# TokenFlow 使用指南

文档导航见 [项目文档](../README.md)，未完成能力和跨平台验收见 [TODO](../TODO.md)。

先看 [中文演示](../media/quickstart.mp4)。下面分开说明官方账号登录、来源模型反代和独立 API 接入。

点击窗口关闭按钮只隐藏工作台，TokenFlow 会在后台继续运行，网关连接不受影响。通过菜单栏／系统托盘的「打开工作台」返回；选择「退出 TokenFlow」才会停止服务并退出。macOS 的 ⌘Q 也会完全退出。

## 1. GPT / Codex 多账号：添加、切换、重启

1. 打开 **账号授权 → Codex → 添加 Codex 账号**，在官方页面用需要的 ChatGPT / OpenAI 账号授权。添加第二个账号时在官方授权页确认登录的是另一个账号。
2. 授权完成后，每个账号有独立标签。选中账号查看模型与可查询额度；**刷新** 只更新当前平台。额度查不到不一定表示授权失效。
3. 打开 **本地 Agent → Codex → 官方登录账号**，选择目标账号。凭据完整且配置可安全修改时，程序备份原状态并切换本机登录。
4. 保存工作、结束生成，**完全退出并重新打开 Codex**。macOS 可使用重启入口；其他系统手动退出重开。只关窗口或刷新 TokenFlow 页面不能保证 Codex 重新加载登录。
5. 在 Codex 确认当前账号和模型，发起实际任务。官方直连不经过 TokenFlow 网关；支持的本机日志可另外索引用量，不能与网关请求重复累计。归属范围见 [用量说明](../testing/usage-attribution.md)。

**设为本机登录** 也可从账号页面使用，之后仍需重开客户端。Codex 切换时已有网关连接会先恢复原接口。需要撤回登录切换时使用 **恢复切换前的本机登录**；接口配置恢复则使用 Agent 页的 **恢复原配置**。

WorkBuddy、WorkBuddyAI、Qoder 的官方身份与自定义模型分别保留：接入网关后官方账号仍选中，标注“已登录”；切换／恢复官方账号不会自动移除自定义模型。实际使用哪个模型由客户端菜单选择，详见 [共存规则](../testing/official-login-coexist.md)。

账号授权管理的是 TokenFlow 保存的来源凭据；官方登录选择控制的是 Codex 自己的登录。它不会切换 ChatGPT 网页 Cookie。TokenFlow 重启后保留已保存来源，但 Codex 是否加载新登录仍取决于它是否重新打开。

Claude Code、Antigravity 也有支持的原生登录切换。按界面提示先退出目标客户端；不要假设所有平台都支持在运行时改登录。

模型目录按来源账号查询，平台「刷新」会重新查询。失败时显示查询状态；只有仍有效的最近成功目录才能继续使用，不把静态旧模型表当作账号的实时权限。客户端里的显示名称与实际请求 ID 可能不同，以复制的 ID 为准；新模型不会自动加入已导出的 Key 权限。旧版模型发现策略已移入历史归档，不能作为当前行为说明。

## 2. WorkBuddy 来源：额度查看与反代到 Codex

1. 在 **账号授权 → WorkBuddy** 添加账号，按官方授权流程完成登录；已有支持的本机授权可用 **从本机导入**。
2. 刷新平台，核对来源账号、可用模型与套餐资源包。WorkBuddy 额度常以套餐点数 / 算力显示，模型列表使用账号共享额度。
3. 打开 **本地 Agent → Codex → 选择模型**，展开 WorkBuddy 来源账号，选择一个或多个模型，点击 **应用所选模型**。
4. 程序备份 Codex 原配置、生成受限网关 Key，并写入接口和模型菜单。确认一次自动重启后，程序会退出 Codex、应用更改并重新打开；选择写入的精确模型。
5. 在 Codex 发起实际请求，到 **活动** 检查来源模型、状态、输入 / 输出 tokens，再刷新 WorkBuddy 额度核对厂商侧变化。

调用仍由 WorkBuddy 来源提供服务并按它的规则计费。网关 tokens 是请求用量，来源套餐点数是上游计费口径，两者不能直接相减。未返回额度时应视为未知，不据此认定无限额。

## 3. Qoder 来源：反代到 Claude Code 或其他 Agent

1. 在 **账号授权 → Qoder IDE** 添加 Qoder 来源账号，按授权页完成登录；等待模型目录，刷新套餐 / 加购 / 组织资源包等可查询额度。
2. 在 **本地 Agent → Claude Code → 选择模型** 展开 Qoder 来源卡片，选好模型后点击 **应用所选模型**；多个模型时，在应用窗口中选择默认模型和快速模型，再点击 **应用**。也可选 Codex、WorkBuddy 或 Qoder 独立应用作为目标，具体组合需要实测。
3. 重启对应客户端加载接口和模型。Claude Code 的终端与 IDE 共用接入配置；操作前先结束生成。Claude Desktop 通过客户端切换入口打开，同样在应用模型时选择默认／快速模型；模型列表旁不再提供单独的「默认模型」按钮。
4. Claude Code 使用 Messages 接口；模型名以复制的精确 ID 为准。当前界面提示自定义菜单需要 2.1.242+，旧版可用 `/model 模型ID`。
5. 请求结果在 **活动** 核对，再刷新 Qoder 来源额度。文本成功不代表长工具名、工具执行、图片或自动审批等全部能力通过。

**来源 Qoder IDE ≠ 目标 Qoder 独立应用。** 前者提供授权和模型，后者是使用这些模型的客户端。如果把其他来源接入 Qoder 独立应用，重启后在自定义模型菜单选择 `TokenFlow · 模型`；WorkBuddy 目标则在新任务输入框下方的模型菜单选择。

Qoder 独立应用重新接入时，会先备份完整当前配置，再覆盖 `providers.token-flow` 的接口、Key 和模型。支持用户在 Qoder 内修改此供应商、移植旧配置后重新接入；其他供应商、工具设置和偏好保留。损坏的 JSON 或写入期间再次发生的修改仍会停止，不会清空整份设置。

已有 TokenFlow 接入记录后，CC Switch 等工具更改了配置，可在本地 Agent 页面点击 **重新应用**，确认后先备份当前配置再应用所选模型。它不会仅因检测到变化就自动写入；确认后配置又被修改时，取消并重新操作。Codex 的重新应用与自动重启合并为一次确认，Windows 实机兼容仍按专门清单验收。

Pi Agent 接入官方 Pi Coding Agent，使用官方像素图标及 `@earendil-works/pi-coding-agent`；导入后在 Pi 的 `/model` 菜单选择 TokenFlow。DeepSeek Harness 接入官方桌面客户端，导入后在应用内选择模型。各 Agent 导出的模型显示名称使用网关里的同一名称；DeepSeek Harness 与 Pi 使用模型的 `name` 字段。`/v1/models` 也返回一致的 `name` 和 `display_name`，实际请求 `id` 保持稳定，例如 `qoder/kmodel_latest` 显示为 `qoder/Kimi-K3`。已导入的旧配置需在新版中重新应用所选模型并重启客户端；只显示 ID 的第三方客户端仍可能展示请求 ID。

每个 Agent 名称旁的下载图标用于安装或更新，确认有可用新版时显示红点。未安装时提示安装，完成后自动识别，无需手动检测。DeepSeek Harness 配置保存后可立即重启桌面应用；Pi 和 Claude Code 保存配置后仅显示结果提示，不自动弹出重启页面；需要重新加载时，可从名称旁手动打开终端或重启。Pi 已有交互会话可选择对应目录重启并进入续聊列表。重启前请保存工作并结束生成。联网检查失败或版本未知时不显示更新红点。

打包目标为 macOS Apple Silicon、macOS Intel 和 Windows x64，各自使用同架构的 Electron 与 sidecar。分别使用 `npm run package:mac:arm64`、`npm run package:mac:intel` 和 `npm run package:win` 构建。Windows 从用户安装目录、Program Files 和 Microsoft Store 包检查桌面程序，Codex、Qoder、WorkBuddy、DeepSeek 可在界面中重启：只请求应用自己的窗口关闭，不强制结束进程；若应用最小化在托盘，需先从托盘退出。Claude Code 是终端程序，修改配置后在原终端重新运行即可。官方 Pi 使用跨平台 Node.js 安装。DeepSeek 官网目前仅提供 Apple Silicon 的 Mac 桌面包，Intel Mac 会明确提示暂无兼容版本，不误用 ARM 安装包。

## 4. 其他应用：导出受限 Key

1. 打开 **API 代理 → 创建 Key**，填写名称和用途。
2. **选择导出模型**，展开 WorkBuddy、Qoder 或其他来源，只勾选这个应用允许调用的模型。
3. **生成 Key**，复制详情中的地址、Key 和模型 ID，按目标应用要求选协议。
4. 在目标应用发送请求，再看 **活动** 和 Key 的 **使用情况**。来源授权与本地 Key 分开；不要把上游凭据发给客户端。

三种接口使用同一份权限目录：

| 客户端协议 | Base URL 与路径 |
| --- | --- |
| OpenAI Responses | 详情中的 OpenAI Base URL + `/responses` |
| OpenAI Chat Completions | OpenAI Base URL + `/chat/completions` |
| Anthropic Messages | 详情中的 Anthropic Base URL + `/v1/messages` |

以下示例用环境变量保存从界面复制的值，替换为当前 Key 已授权的精确模型 ID。`TF_BASE_URL` 是详情中的 OpenAI Base URL，通常已含 `/v1`。

```bash
curl "$TF_BASE_URL/responses" \
  -H "Authorization: Bearer $TF_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"workbuddy/实际模型ID","input":"Reply OK only.","stream":false}'
```

同一个 Key 可以授权两个来源，客户端分别传入 `workbuddy/…` 或 `qoder/…` 的模型 ID。来源名称不是模型 ID，以界面复制结果为准。Key 可修改模型权限、停用、删除；清空权限后不能调用模型，新增来源不自动扩大旧权限。

用量有三类：官方来源额度、Key 的累计 tokens（预算计数），以及经过网关的请求台账。台账按天保存在本机（最多 180 天），记录请求数、失败数、输入、缓存读取、缓存写入、输出、工具调用与返回次数、耗时；可在「本地 Agent」（总览及各 Agent）、「API 代理」和「活动」页按今天 / 7 天 / 30 天 / 全部查看，并按来源账号（旁边显示官方额度）和模型拆分。总 Token = 含缓存的输入 + 输出；未缓存输入、缓存读取、缓存写入分别展示，推理 tokens 已包含在输出中，不重复相加。缓存命中率 = 缓存读取 ÷ 上游返回了缓存字段的请求的输入；未返回缓存字段的部分显示「未拆分输入」，不会视为缓存未命中。流式响应使用最终用量记录，中断前已返回的用量仍保留，各次重试分别计入。生成速度只基于实际流式输出阶段统计。

「调用轨迹」显示请求链、模型、协议、耗时、tokens、工具名称、调用与返回状态，展开详情可查看工具返回结果。只保存统计与工具结果，不保存完整用户消息、助手回答、推理正文或工具参数。工具结果只在首次收到时计数，重复传入的历史不会重复累计；常见凭据会隐藏，单个结果最多保存 16 KB，二进制附件只保存类型摘要。轨迹在本机最多保存 30 天、1,000 条及 16 MiB，详情仅管理员可读取。图中的工具标记表示结果收到的时间，不代表工具执行耗时。

官方登录直连厂商的用量不在网关台账内；有可读取的本机记录时会纳入本机统计。后端支持 Key token 预算，当前创建界面默认不限额。Cursor 此类远程接入需要外网可达 HTTPS，不能直接填本机 `localhost`；应用不自动发布公网网关。

账号授权、本地 Agent、API 代理的用量入口默认只显示图标、Token 数和缓存命中，点击弹出输入、缓存和输出拆分；暂不展示更多统计与轨迹。本地 Agent 页仅显示当前 Agent 的用量。API 接口页仅管理接入，不显示用量明细和统计；其用量在设置总览及对应 Agent／Key 中查看。

**设置 → 用量总览** 合并网关台账与本机 Agent 记录，显示累计 Token、每日峰值、活跃与连续天数，并提供近一年活动热力图（每天／每周／累计）。悬停或聚焦日期立即显示 Token 数，点击一天查看按 Agent 的明细；官方账号、上游 API Key、未标注渠道按认证来源拆分，本地 Agent 与 API 代理按使用方式拆分，这两个维度不能重复相加。

本机记录读取 Codex、Claude Code、Qoder、WorkBuddy、官方 Pi、DeepSeek Harness 的会话用量。后台索引只缓存用量元数据，不复制对话正文、工具参数或凭据，不修改原会话；首次索引显示进度，后续仅重读变化文件。Codex 逐响应与累计通知只保留一种，流式片段按响应去重，带有 TokenFlow 路由标记的本机请求不重复计入网关台账。WorkBuddy 的上下文占用快照不作为消耗量。归属账号只使用已记录的计费账号标记，不用会话创建账号或当前登录账号猜测历史；缺失渠道、账号或本机记录的部分会说明，网页端和云端未落地的历史无法读取。官方额度保持原样，不换算成 Token。

## 5. 独立 API 接口

**API 接口 → 添加 API** 填名称、Base URL、上游 Key、模型 ID。模型可逐项添加或逗号分隔，当前界面最多 50 个；用第一个模型的最小文本请求识别协议，验证会消耗少量额度，其余模型仍须有权限。

保存后可复制模型列表、编辑、启停。只改名称不重新验证，密钥默认隐藏；显式显示 / 更换由独立按钮操作。修改正在使用的来源提示影响，有引用的来源不能直接删除。随后按上述 Agent 或 Key 流程接入。

## 6. 换模型、退出网关与维修

已接入时 **管理所选模型** 可跨来源多选，搜索账号 / 模型并再次应用。**设为默认** 保留其他选项；同请求模型 ID 只绑定一个来源账号。至少保留一个，或 **恢复原配置** 退出网关。

切换 Codex 网关时，会迁移符合条件的本机对话，并恢复由网关创建的子任务路由；不接管其他无关自定义来源。在 macOS 和 Windows 上，保存工作后点击「确认并自动重启」，程序会自动退出 Codex，再应用更改并重新打开。首次迁移保存数据库基线、相关对话原始记录与配置；新增对话追加增量备份。已迁移且模型仍获授权的对话直接跳过。来回切换、新增/移除所选模型和新建项目后，会通过 Codex 原生恢复接口保存目标来源与模型，不发送测试消息。切回官方前必须恢复旧对话路由，避免移除 `token_flow` 后旧对话仍引用它。源端条目 ID 的必要清理和分页偏移修复属于续接兼容处理；可选的额外 checkpoint/reasoning 处理仍受用户选项控制。缺失原始历史的对话会保留失败记录与现有备份，不能保证恢复。本机已有备份及增量索引仍保存在应用数据目录的 `codex-thread-backups`（请整体保留，增量记录可能引用其他批次的数据库基线），不会自动覆盖后续历史。图片仍取决于所选模型和上游的真实图片能力，文本模型不会因为迁移而支持图片。显式子智能体模型和自定义 Agent 文件仍有自己的优先级。

Codex 图片能力由上游模型目录传递到本机目录，不再将所有模型一律标为纯文字。只有上游明确支持且代理适配器能传递图片时才启用；未知模型保持纯文字，Qoder、Cursor 当前适配器不声明图片支持。更新 TokenFlow 后需重新应用所选模型，并由客户端重新加载模型目录。此能力声明不替代真实上游图片识别验收。

**维修师傅 → 修改 Agent 配置** 不需要维修模型：选目标与来源，生成方案，预览接口 / Key / 模型，确认后备份并写入。对话维修则先选维修模型；收起保留会话，正在生成时使用 **停止**。上游 Key 保存到 API 接口，不放入对话。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 切账号后仍是旧账号 | 完全退出重开目标客户端，检查官方登录与网关模式是否混淆。 |
| 模型菜单没变化 | 重开客户端，检查版本、项目设置和旧终端环境变量。 |
| Codex 重启入口一直提示尚未退出 | 当前重启检测可能误计入 ChatGPT 进程，先手动退出重开 Codex。 |
| 来源有账号却没有模型 | 启用并刷新当前平台，核对套餐、账号权限和目录同步状态。 |
| 最小文本成功，真实任务失败 | 核对协议、工具、上下文及来源真实错误，分别验证客户端能力。 |
| 查询不到额度 | 视为未知或旧结果，不认为无限额，也不要重复登录代替检查。 |
| 需要恢复登录或配置 | 先退出客户端并停止其他配置编辑，再使用对应恢复入口。 |
| 写操作超时 | 刷新核对结果后再操作，避免重复写入。 |

演示使用虚构账号、额度和模拟上游；客户端示例验证的是配置加载、网关请求、来源路由与用量记录。真实厂商授权、实际扣费和目标 Agent 完整对话仍需在自己的环境确认。反馈前去掉账号、凭据、请求正文、回调和本机路径。

历史渠道识别优先使用记录中的认证方式；Codex 还会读取本机诊断数据库，仅使用同一对话两分钟内的推理请求地址。多个渠道冲突、只有模型名或当前登录信息时不猜测。代理返回的响应标识与本机记录精确匹配后，会排除本机副本；带有网关路由标记的记录也会排除，复制会话与流式片段按响应标识去重。索引仅保存计数及散列标识，不保存完整消息、认证凭据或请求地址。

模型列表默认 API 来源优先并按名称自然排序（A–Z／Z–A），选择在账号模型、本地 Agent、API 接口、模型选择页和 Key 详情之间同步；API Key 默认按名称 A–Z 排序，API 来源优先，也支持最新创建和累计 Token 排序。模型和 API Key 均可通过拖动把手调整顺序（也支持方向键），拖动后自动切换为手动排序，保存在本机，退出并重新打开后仍保留。筛选时只调整可见模型，其他模型的排序保留。排序仅作用于展示。API 代理卡片显示名称、用途、排序后的前三个模型与累计 Token，亮暗表示启用状态。点击卡片从右侧打开完整详情页，启用、停用和删除都在详情页内操作；删除前可以取消确认。模型选择及其他详情页面也从右侧进入主内容区，小窗口使用整页布局。

账号授权页将用量入口放在已选平台的操作栏，默认显示图标、Token 数和缓存命中，点击查看拆分；不重复显示平台名称、授权提示或下拉箭头。

WorkBuddy 的「添加账号」使用国内站，「添加海外账号」使用 `www.workbuddy.ai` 官方登录页。海外账号单独保存并标记「海外」，模型目录、额度、推理和令牌续期均使用所属站点，不合并国内与海外额度。完成海外登录前不能验证该账号的实际可用模型和余额。上游明确返回 11128（调用渠道未获批准）时停止该请求，不通过改写客户端身份、移除规则或反复重试绕过。


WorkBuddy 模型来源使用官方 CodeBuddy Agent SDK。TokenFlow 覆盖默认编程 Agent 提示词，把调用方系统指令放到 SDK 的 systemPrompt 层；SDK 公开输入只支持用户消息，因此历史 assistant / tool 消息仍以包含角色、调用 ID 和结果的结构化文本传入，不宣称原生消息完全透传。关闭内置工具、磁盘配置和会话持久化；客户端工具仅登记为待执行提案，由 Codex / Claude Code 等调用方执行。SDK 正文增量实时转换为 Responses、Chat Completions 或 Anthropic Messages 事件；工具提案与最终用量在结果验证后返回，思考块不会冒充正文。

Qoder 来源由项目内 CLIProxyAPI 的 Qoder 适配器直接请求 Qoder 服务，并不启动官方 qodercli Agent；CLI 渠道字段是上游请求格式。调用方负责 Agent 提示词、工具执行和长任务管理。不要把该通道与官方 Qoder Agent SDK 的本地 CLI 运行时混为一谈。


Qoder / WorkBuddy 转换 Claude Code 请求时保留 `tool_choice.disable_parallel_tool_use`，映射为禁止并行工具调用。上游无视串行要求返回多个工具时，网关明确报错，不将该结果标为成功。Qoder 流读取支持有界的大块工具参数（单条 SSE 上限 16 MiB），取消会关闭上游读取；独立 usage 事件纳入最终 Token 统计。Qoder 的 0/0 Credits 资源包标记为未分配，不按剩余 100% 显示。Token 统计与厂商 Credits 各自使用实际返回值，额度未变化不等于免费。

Qoder 请求将所选模型的官方 key 同步到 `X-Model-Key`、`model_config.key` 和上下文模型配置，不依赖缺少顶层模型标识时的上游默认行为。已验证漏传顶层 key 会出现有输出但 `billable:false` 的响应，不能据此判断免费政策或实际模型质量。网关运行日志单独保留上游 `billable` / `credits` 数值（包含 false 和 0），不记录账号认证或消息正文，不把 Credits 换算成 Token。额度页仍以官方额度查询结果为准。
