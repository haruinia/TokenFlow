# Codex API 直连：共享 custom

用户决定：API 直连采用 CC Switch 式共享 `custom` provider；官方直连、网关和统一网关继续原有的配置恢复、协议迁移及上下文处理流程。

## 实现边界

- `CodexApiAccess` 只协调配置切换，`CodexApiDirect` 负责配置事务与模型目录。新 API 直连使用原 Codex 数据目录，不创建独立 home，不迁移、复制、归档或压缩对话。
- API A/B 共用 `custom`；替换该表的地址和密钥、默认模型及保存过的模型能力目录。应用不发探针。官方 auth.json 保持原样，不再强制 `forced_login_method=api`。
- 进入 API 时保留原 `openai`/`token_flow` 定义，让旧会话仍可加载。暂停统一网关的受管模型说明，保留用户自己的指令。退出配置覆盖层时恢复全部原有字段，再按用户选择执行原有官方或网关流程。
- 无原 `custom` 定义时，退出后保留无凭据的休眠定义，避免 API 会话打开时报 provider missing。已有用户 `custom` 定义则精确恢复。
- 级联删除来源在 API 配置覆盖层之下更新原网关配置，再恢复仍有效的 API；删除正在使用的来源时退出该 API。
- 共享 `custom` 的记录不再包含唯一来源 ID：本地统计保留 API 分类，不凭保留的 ChatGPT 登录推断付费账号；确定的官方网络证据仍优先。旧唯一 ID 的来源归属仍可读取。索引升级为 v21，重读相关 Codex 用量缓存。
- .97 已创建的独立目录及记录保留，不自动合并。旧选中状态在显式切换前仍可读取；下次应用 API 后使用共享目录。此兼容分支不再创建独立会话目录。

## 验证

- 配置与服务回归：官方/统一网关→API A→API B→原配置；官方登录保留；原自定义 custom 恢复；用户指令与 v1 协议恢复；直接选择官方账号；级联删除正在使用及底层引用的来源；旧 .97 记录保留。
- 本机原生引擎 `codex-cli 0.166.0-alpha.5.1`，隔离 HOME、合成 ChatGPT 凭据与本地模拟接口：API A 创建对话并生成可读摘要，切 B 后以同一 thread ID 续聊，实际请求携带摘要并使用 B 的凭据；退出 API 后仍能打开该 API 对话。
- 同一原生引擎的统一网关协议往返测试：返回共享 API 配置覆盖层后，官方/网关模型继续使用 v1，原生网关子代理实际完成；恢复原接入时恢复原 v2。
- 类型检查及生产构建通过。相关回归包括 Codex API、官方账号切换、协议迁移、模型发现、本地用量索引以及 Claude API 的既有行为。

结果：`results/codex-api-shared-continuation-2026-10-31.json`、`results/codex-unified-shared-api-protocol-2026-10-31.json`。仅验证原生客户端与产品配置路径；没有发送真实计费请求，不能据此断言任意第三方接口都能理解官方加密历史。本次未修改生产 Codex 配置、重启应用或安装新包。
