# 旧会话协议迁移与备份占用核查

2026-10-29，America/Los_Angeles。本轮为调研和隔离验证，未修改产品迁移逻辑、真实配置、认证或会话；未删除备份，也未重启实际客户端。

## 协议迁移的范围

现有 `CodexThreadMigration` 通过 `thread/resume` 迁移 provider/model，并验证数据库路由已保存；已经是 token_flow 且模型允许的会话会直接跳过。它没有迁移或校验 `session_meta` / `turn_context` 中的 `multi_agent_version`。统一目录设置 v1 不会覆盖旧会话保存的 v2，甚至旧会话从未派发过子代理也会遇到这个问题。此前证据见 [旧会话实验](old-subagent-encryption-research-2026-10-28.md)。

应将协议纳入已有迁移事务，而不在每次推理时猜测或修改密文：

1. 进入统一网关：目标父会话的有效协议为 v1，provider/model/protocol 都通过验证才能标记迁移成功。已经迁过 provider 的旧会话也应检查协议，不能继续被路由捷径跳过。
2. 在统一网关目录内切换到官方模型：仍然是 token_flow 模式，保持 v1；这样下一次选择网关子代理仍可派发。不能把选择一个官方模型误判为退出统一模式。
3. 退出统一网关、恢复原生官方接入：恢复迁移前的协议设置。原设置通常为 v2，但原来是 v1、disabled 或由原生默认决定时，应保留该语义，不统一硬写 v2。统一模式中新建的会话没有旧协议，应按恢复目标的原生能力决定。
4. 恢复处理针对当前完整历史，只撤销受管理的协议设置；不得把迁移前整份 JSONL 覆盖回来而丢掉后续对话。保存必要的字段前像、版本/指纹及恢复意图，复用现有备份和投影索引修复。

普通消息、工具调用/结果、原生 reasoning/compaction 和已有 agent_message 的内容不属于协议元数据变更范围。子代理协议 v1/v2 与远程压缩能力 v2 是两个独立概念。已存在的密文任务不会因为元数据改为 v1 而解密；既有子代理不能被当作普通父会话直接批量改写。

- 迁移备份有 78 个批次目录、66 个清单（65 restored，1 migrated）。14 份数据库文件约 5.60 GB，1,437 份 JSONL 约 9.68 GB。按清单会话身份关联，206 个会话分别存在多份完整基线，总计 986 个文件、9.25 GB。这证明相同会话被多次整份备份，不证明各版本内容逐字节相同；未对正文做哈希扫描。
- 上下文转换备份有 47 个批次，18 份 `thread_history_1.sqlite` 合计 15.27 GB；数据库占该目录约 98.5%。整库副本集中在 10 月 15—21 日。数据库版本可能不同，不能按同名直接删除。
- 当前增量仓库含 695 个完整基线引用、3,992 个差分文件。差分约 0.986 GB，对应的各历史完整版本大小之和约 32.62 GB；该统计是多版本之和，不是当前活跃历史大小。

### 当前代码已在复用，但未回收早期副本

- 59 个迁移清单复用已有数据库基线，4,602 个条目使用基线引用，指向 313 个历史文件。本次未发现这些引用缺少目标文件。
- 23 条上下文转换数据库引用指向同一现有数据库，不再每次复制整库。
- 增量仓库 695 个基线中，605 个直接依赖迁移目录中的旧文件；没有发现基线缺失或 parent 元数据缺失。不能把 restored 清单所在目录直接视为可删除，否则可能断开当前增量链。
- 现有差分按相同路径复用一个连续前缀/后缀，中间保存为 delta。28 个大于 1 MiB 的差分已接近整份历史大小（至少 90%），合计约 650.5 MB：多处元数据变化时，单个连续差分不够节省。路径变动也不会自动获得跨路径内容去重。
- 未发现历史备份仓库的引用闭包回收实现；现有文件清理规则把整个 codex-thread-backups 目录列成待确认项，尚不知道其他仓库对它的依赖。

验证当前复用逻辑的 4 个定向回归测试通过：跨完整切换周期复用基线、同次迁移新增会话不再整库复制、新会话共享数据库、历史追加仅保存增量。使用合成数据，未执行真实迁移。

## 建议的结构

保留一个迁移协调层管理路由、协议、投影校验及失败恢复；协议变换独立于普通消息转换。备份仓库统一负责不可变内容和引用，清单只表达每次迁移的状态与恢复点。

新增协议字段变更应保存小范围可逆差异并复用既有历史基线；同内容跨路径/批次可通过内容标识复用，多个分散变更不应退化为整份中间历史复制。旧副本整理先建立所有 manifest、full、parent 引用的完整关系，再验证/合并等价内容，原子更新引用后才释放无引用版本。数据库基线的用途与时间点必须明确，不能因为文件同名就当成等价恢复点。

不需要再加一套请求时临时降级，也不应把备份目录一刀切删除。当前核查没有给出精确可释放字节数；要得出该值还需要内容一致性和 APFS 共享块核验，以及明确保留哪些历史恢复点。
