# UI 反馈位置与应用模型窗口验证

记录日期：2026-10-22。对应 TODO `UI-001`；交互规则见 [界面设计](../design.md)。

## 问题与改动

维修侧栏打开时，旧 CSS 把通知的 `right` 改为 `456px`，覆盖了右下定位；已移除这条偏移。Thinking 原先分别出现在按钮、弹窗标题、迁移内容和页面操作层；现由共享组件登记加载请求，一个反馈层在视口中央显示，关闭的弹窗不登记请求。

本地 Agent 配置写入原先只在完成后提示结果或重启；现在实际应用开始时立即打开固定窗口，保存结果、错误、重试和重启选择均保留在该窗口内。沿用原有 `FlowDialog`、Thinking 动画和 Codex 迁移进度，没有改变配置写入、备份、迁移及客户端重启的后端逻辑。

以上是源码检查、临时目录的后端回归和浏览器界面模拟。本轮未安装或覆盖桌面应用，未修改真实客户端配置、登录或对话；不同处理器与 Windows／Linux 安装包的真实等待时间和重启行为仍待实机验收。

## Claude 默认模型入口修正

保留 Claude CLI／Claude Desktop 客户端切换及桌面页面。桌面模型列表旁仅移除独立的「默认模型」按钮，默认模型和快速模型仍在点击「应用所选模型」后的应用窗口里选择；单模型直接使用该模型。恢复原有桌面偏好与状态读取，以及原有用量覆盖名称。

前一轮将用户要求误解为隐藏整个桌面入口，现已纠正；前一轮「没有桌面入口或状态请求」的验证不再作为验收标准。验证应确认桌面页面可打开、独立按钮消失、应用时仍能选择并提交默认／快速模型。

修正后的类型检查与前端构建通过；浏览器模拟确认桌面入口及 CLI／Desktop 切换可用、独立「默认模型」按钮消失、桌面应用窗口中选择的默认／快速模型正确提交，CLI 的应用时选择流程继续可用。未修改真实客户端配置。
