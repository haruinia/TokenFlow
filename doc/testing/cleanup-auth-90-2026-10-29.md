# .90：清理流程简化、本机授权按需读取与两项调研

日期：2026-10-29（America/Los_Angeles）。调研在 10 月 28 日开始。

## 本次产品修改

1. 清理确认页移除“已关闭应用”“已核对影响”的额外勾选和“永久删除”文字输入。用户选择项目、核对确认页后可直接点击确认按钮；服务端仍要求本次扫描 ID、选定项目与明确的删除方式，保留运行应用、文件变化和符号链接检查。没有自动执行真实清理。
2. `.app` 按真实 bundle ID 分组，版本及构建号排序；显示较早版本与同版本副本。安装包按名称系列/格式分组，内容相同继续使用既有 SHA-256 证据。同版本不当作内容完全相同，也不自动选中。
3. 桌面与 headless 入口启用 `nativeCredentialsOnDemand`。启动加载 TokenFlow 自己已保存的账号，不再全量自动导入本机客户端；未主动读取的 provider，其状态 GET 返回 `not-inspected`，用量归属观察也不读取该客户端。Codex 共存预检同样不在被动 GET 中读取 auth.json。
4. 点击本机导入只授予本次进程中对应 provider 的读取；已保存账号的主动切换先通过独立 POST inspect 获取该客户端的真实 revision。两者都保留原生系统权限校验，不推导其他 provider 的授权。
5. 启动时的安全存储选择只针对 TokenFlow 自存凭据。跳过后，用户明确发起导入可以按需启用系统安全存储，无需重启；启用失败仍保持跳过状态，不替换正在使用的内部网关 Key。
6. Codex 用量记录器启动时只做日志统计；官方账号快照需显式 Codex 操作后才启用。已授权 provider 的后续状态/用量观察在本次进程内可刷新，重启后重新回到尚未检查状态。

本次没有实现“全部凭据只存路径”，没有迁移或删除既有授权。客户端配置读取仍可能涉及内嵌 API Key，不能把“不自动扫描导入本机认证”描述成“运行时从不接触 Key”。

## 调研结果与未实施范围

- [旧对话子代理协议](old-subagent-encryption-research-2026-10-28.md)：真实安装引擎与隔离会话稳定复现 422。旧会话持久保存 v2 协议；改配置、退订重载、重启均不改变。离线修改合成会话副本的协议元数据后，未来派发采用 v1 明文，历史 response_item 字节不变。未修改真实会话；存活子代理、等待/取消、fork、同步边界仍需在产品迁移前验收，已有密文任务不等于可恢复。
- [DeepSeek 直连](codex-direct-api-research-2026-10-28.md)：官方已提供 Responses 与 Codex 接入说明；实际安装引擎使用独立 provider、合成 Key、本机假上游验证了直连请求。未使用真实 API Key 或改现有 provider；不同托管商需单独验证，旧密文历史与长对话仍需测试。
- [凭据引用方案](local-auth-on-demand-research-2026-10-28.md)：目前 sidecar auth-file、授权历史、OAuth 刷新和 Cursor 独立 SDK Key 不能简单换成一个路径。部分来源可设计文件/钥匙串/命令引用并减少长期副本；运行时仍需读取凭据值。
