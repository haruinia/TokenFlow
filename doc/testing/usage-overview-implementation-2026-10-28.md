## 实现边界

- `usage-accounting.ts` 负责已归一化的包含式输入/输出核算。缓存和推理是子集，不再加一次。质量分完整、部分、未知、字段冲突；只知道总量时保留未拆分 token，冲突不通过截断缓存伪装完整。
- `usage-facts.ts` 保存不含提示词、回答、凭据的 SQLite 请求明细，WAL + FULL 同步。客户端 HTTP 请求有独立 eventId；同一事件晚到的计量更新原记录。不是把一条用户消息当成一次请求，也不是每次上游重试都额外记一条。
- 旧 JSON 日汇总只导入一次，保留为历史汇总；JSON 仍导出兼容视图。新明细可重算；沿用本机日界线和 180 天保留策略。无法从旧日汇总重建逐请求身份，旧漏计不会凭空补回。
- SQLite 锁定/写入失败时保留内存待写队列，用相同 eventId 重试并显示告警；坏库不覆盖、不阻止推理启动。坏库降级期间新记录仅在内存，告警明确指出尚未持久保存。校验失败隔离在统计副作用边界。
- 官方账户只从当前请求明确的账户头生成 hash；会话和响应标识也只留 hash。不会把历史用量归给当前登录账户。
- 本机 Codex 候选通过唯一响应 hash 与兼容的已知计数补齐已有事实，不另加一次消费。缺失缓存、写缓存和推理字段不当作 0；已知字段冲突不覆盖。无精确匹配、同 hash 多条网关请求时不猜测。
- 子代理分类来自实际 session_meta 的 thread_spawn 关系。父会话镜像不覆盖真实子会话归属；冲突关系保持未知。分类不增加总量。任务用途不是完整父子成本树；无法证明的用途显示“未标注用途”。
- 总览卡片、模型/来源/任务分类遵守同一个选中日/周/累计范围；热图、条形图、维护助手计量均纳入已知未拆分量。既有本机日志缺少完整质量证据时保守归为部分/未知，不冒充完整。
- “本机日志”表示数据来源，不再用它证明网络直连。官方额度百分比不换算 token；Qoder Credits 保持独立单位。

没有修改 provider、子代理派发、压缩、上下文加解密或账号登录配置。没有调用真实模型进行测试，也未重写生产账本。

## Standards review

第一轮发现统计写入错误可能传到流的 flush、原生对账覆盖已知缓存、历史质量重复分类；均已修复并加入隔离回归。复核追加发现 null 缓存被当作已知 0，已改为安全非负整数判定并覆盖 null、负数、小数。

剩余非阻塞建议：大量明细场景可继续优化内存中明细排序/分页。当前响应匹配使用索引映射，180 天保留范围内加载明细；未宣称百万级明细性能已验证。

## Spec review

复核发现同响应父子镜像的扫描顺序影响任务分类，以及明确 0/0 用量被过滤。已分别独立合并关系证据、保留明确零样本，并增加正反顺序、关系冲突、零用量对账测试。

历史汇总、未知数据、失败请求与计量质量均有独立口径；未扩大到费用估算、完整任务树或上游请求执行日志采集。
