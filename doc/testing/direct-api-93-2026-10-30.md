# API direct .93

## Behavior

- Codex and Claude Code CLI share the local configuration transaction, private backup journal, revision checks and owned-field restoration. Codex keeps its existing journal layout for .92 compatibility.
- Applying direct mode reuses the saved per-model URL and protocol. It makes no inference/probe request. Optional API discovery and validation remain part of source setup.
- Codex requires Responses; Claude Code requires Messages. Incompatible saved routes remain visible but unavailable for direct selection.
- The local Agent section is named “直连”. “添加 API” opens a model selector with a single “应用” action. Removed the repeated probe and long technical explanations.
- Claude Code settings take effect on its next invocation; Codex retains its existing restart transaction. Official credentials remain intact. Switching to a gateway or saved native account first restores the direct configuration.

## Evidence

- 36 tests in seven relevant suites passed, including exact restore, conflicts, saved-account visibility and API/gateway/native-account transitions.
- Service integration tests assert zero supplier requests during apply and restore.
- Actual installed Claude Code executed against a local synthetic Messages server in an isolated config directory using `--bare`. One request reached `/tenant/anthropic/v1/messages` with the selected model and fixture API key, returning `DIRECT_OK`. No real provider request or user credential was used. See `results/claude-api-direct-native-2026-10-29.json`.
- Production UI fixture verified Codex’s saved account under “直连”, the Claude CLI API selector, direct apply and restore. The fake saved provider pointed at an unavailable local port; application still succeeded without probing.
- Typecheck, production build, signing verification and all 20 packaged-runtime check categories passed.

## Installation

The .93 app bundle is staged and replaces the installed bundle without terminating the running gateway. The prior bundle is retained. The install receipt records the package hash, HTTP availability, preserved processes and unchanged Codex configuration/auth hashes. The user must reopen TokenFlow to load .93; no running-version claim is inferred from the bundle on disk.

This verification establishes native request/configuration compatibility, not availability of every third-party API or model.
