# .91：旧会话协议迁移与备份复用

用户确认的流程：进入统一网关时一起迁移 provider、模型和子代理协议；网关内所有模型保持 v1；退出统一网关恢复原协议；备份完成后复用并核对引用，再整理无依赖副本。

## 实现

- `codex-agent-protocol-migration.ts` 仅处理 session_meta / turn_context 的协议字段，保存实际观测前像和原生恢复目标。原来是 v1、v2、disabled 或 absent 的会话分别恢复原语义；没有旧清单的网关 v2 会话也能进入 v1，退出后由原生默认决定。
- `CodexThreadMigration` 把协议校验纳入迁移，不再因 provider/model 已匹配而跳过旧协议；兼容旧清单原始备份，持久保存 pending 意图，重试时完成历史编辑及索引修复。父代理管理的子会话仍不作为独立父会话批量改写。
- 原生恢复在迁移 runtime 退出后再应用一次协议设置，避免尚未卸载的网关模型目录把 absent/default 重新固定为 v1；完成验证后才把清单标为 restored。
- 官方配置恢复撤销 TokenFlow 写入的子代理 feature 开关及模型说明目录，覆盖根配置和 profiles。以 before/after 对照保留其他设置及不同于已写值的用户后改开关。
- `CodexHistoryEditor` 从上下文转换模块提取公共的离线编辑事务：备份、并发字节校验、原子替换、分支字节边界及投影修复。协议策略与普通消息/压缩转换独立，协议迁移不解密、删改或重标已有任务正文。
- `codex-backup-lock.ts` 使用 proper-lockfile 的跨进程心跳锁，覆盖历史 capture、迁移、编辑和整理；同一操作内部可重入。防止清理与“先写 payload、后发布 revision JSON”的过程竞争。
- `CodexBackupMaintenance` 检查三个仓库的 manifest、历史基线、parent、latest 引用后才整理。macOS 上内容 SHA-256、mode/uid/gid、ACL、扩展属性值均相同的不可变副本可共享 inode，原文件路径及恢复点不变；Windows/Linux 暂保留独立副本。不同数据库版本、旧 restored 清单及不确定的未发布旧批次不会被当成垃圾。
- 仅删除历史仓库中未发布且无任何引用的 payload。引用损坏或整理不能完成时保留旧副本，并在迁移状态返回 retained；不影响仍可完成的正常路由迁移。因 Codex 重新运行而中断则继续停止迁移。
- 同长度、多处小修改使用多个可验证差异片段，避免单个连续 delta 再次复制大段对话。旧 delta 格式继续可读，所有重建版本仍检查 SHA-256 和长度。

复用不会删除仍被增量链使用的旧基线，也不把不同时间点的数据库视为等价备份。共享 inode 后目录逻辑大小可能不变；共享字节计数不是实际释放空间，APFS 还可能原先已共享数据块。

## 验证及 review

- 新增旧协议回归先在原实现失败：迁移后仍为 v2；修复后通过。
- 11 个文件共 220 项相关回归通过，包含配置恢复、旧清单、迁移失败重试、分支边界、普通上下文转换、备份完整性、并发锁、权限和扩展属性、原生索引及生命周期。类型检查、diff 空白检查、生产构建通过。
- 原版引擎 `0.165.0-alpha.1.2` 与实际产品迁移类的隔离测试通过：[脚本](prototypes/codex-protocol-product-migration.mts)、[结果](results/codex-protocol-product-migration-2026-10-29.json)。旧清单中同一父会话由 v2 变为 v1，原生子代理收到完整明文任务并完成，恢复原 provider 后工具重新为 v2，父会话继续一轮。使用合成供应商、本机 SSE 和虚拟认证，无真实账号或付费推理。
- 两路只读 review 找到并修复：网关旧 v2 前像与恢复目标混淆、发布/清理缺少共享锁、硬链接可能改变权限。追加检查补齐原生配置中的 v1 强制开关撤销。最终复查未发现新的阻断问题。
- macOS arm64 包通过 19 项运行检查及 ad-hoc 签名验证。Antigravity sidecar 与已安装 .90 内容一致。

本次不声称已有密文任务可以解密，也未验证跨设备同步、所有 Codex 版本或切回 v2 后继续调度旧 v1 子任务的全部行为。原版引擎隔离实验验证未来派发及父会话往返，不是付费供应商质量测试。

## 安装与生效

.91 更新到本地应用，.90 保留完整程序备份；实际路径及检查结果见 `release/protocol-backups-91/install-receipt.json`。没有重启运行中的 TokenFlow 或 Codex；新版本重新打开 TokenFlow 后生效。真实会话迁移与备份整理将在之后由用户发起的迁移流程中执行，本轮未修改真实对话或清理生产备份。
