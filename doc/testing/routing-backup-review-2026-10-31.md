# Codex 备份／API 直连与 Claude Code 复核

基于 `4189cb3` 的当前实现，按用户既定的共享 `custom`、不迁移 API 对话、官方／统一网关保留原流程进行 review。生产检查仅读取配置中的路由摘要和备份文件元数据，不读取会话正文、不调用生产模型、不删除备份。

## 发现：变长的分散改写会使增量退化（P2）

`packages/core/src/codex-history-backups.ts:63` 只有新旧字节数完全相等时使用稀疏片段；其他情况保存公共前后缀之间的整段内容。同一长历史的多处模型名或其他元数据变长时，即使实际变化很小，也会重复保存中间的大量正文。

隔离复现：4,001,560 字节的合成历史，只替换 20 处模型名后变成 4,001,880 字节，但增量为 3,801,816 字节（95%）。两个版本都能还原，问题是存储效率，不是本次复现发生数据丢失。见 `results/codex-variable-length-backup-review-2026-10-31.json`。

建议单独修改备份存储层，支持变长记录／内容块复用，保留旧格式读取及所有恢复引用，并验证新旧数据逐字节可恢复。不要为缩小目录而删掉仍被清单或增量父链依赖的文件。

## 本机只读检查

- 对话原文件约 3,208 MiB；三个历史备份目录逻辑大小合计约 45,990 MiB（44.9 GiB）。逻辑大小不是 APFS 实际独占物理空间或可释放空间。
- 其中增量文件约 16,267 MiB，历史 SQLite 副本约 19,905 MiB，其余主要是历史 JSONL 基线。
- 147 份清单、7,143 个修订、31,353 条引用的存在性／目录边界检查没有发现缺失引用。未对全部生产正文执行内容哈希复核；这不是完整恢复演练。
- 当前线程与上下文代码已经复用现存数据库基线；旧版留下的 SQLite 恢复点仍保留。不能将这些旧文件全部认定为本次切换新增或可删除。
- 维护器只自动清理没有发布引用的载荷，不按时间清除历史恢复点。长期空间回收仍需明确保留策略与依赖重建，单靠相同内容去重不会清除所有旧版本。

## 接入边界

| 路径 | 当前实现 |
| --- | --- |
| Codex API 直连 | 共用原数据目录和 `custom`，按已保存的 Responses 路由写配置及模型能力；应用不探针、不迁移或备份对话，官方认证文件保留。API A/B 切换允许旧会话继续尝试使用当前 API。 |
| API → 官方／统一网关 | 先移除 API 配置覆盖层，再运行原有账号／网关流程；`custom` API 会话不纳入官方／网关迁移。无原 custom 时保留无凭据休眠定义，避免 provider missing。 |
| Claude Code CLI API 直连 | 已存在：本地 Agent → Claude CLI → 直连 → 添加 API。读取已保存的 Messages 路由，写 `settings.json` 的 URL／Key／模型，不经过 TokenFlow 转发，不修改对话、账号凭据或压缩记录。 |
| Claude Desktop | 与 CLI 分开的客户端路径；当前产品接入仍走网关，本轮不把 CLI 支持范围扩展为 Desktop 也已支持。 |

生产配置摘要显示：本机 Claude Code CLI 和 Codex 当前都指向 9527 网关。没有代用户切换这些配置。

Claude CLI 的直连选项要求来源中已有 Messages 路由。当前每个模型只保存一个选用协议；同一供应商即使实际支持多个协议，若只保存 Responses／Chat 路由，也不会被当作可直接用于 Claude CLI。不能通过猜后缀或在应用时重新探针来绕过用户的保存选择；以后若要让同一来源同时支持两种直连，应扩展为保存多协议路由。

## 验证与限制

- 71 项现有相关回归通过：Codex API 配置／服务、Claude API 服务、历史增量、备份引用维护、迁移排除 API 会话。
- 已安装 Claude Code `2.1.309` 的隔离原生客户端测试通过：只向合成上游的 `/tenant/anthropic/v1/messages` 发请求，模型和 Key 一致，没有 TokenFlow 中转或生产供应商请求。见 `results/claude-api-direct-native-2026-10-31.json`。
- API 配置事务仍采用排他锁文件；异常退出可能遗留锁，当前策略要求核对后恢复，不自动抢占。其余连接配置也共享这个锁约定；若后续改进，应统一处理，不能仅让 API 层绕过。
- 任意旧会话跨第三方 API 的加密上下文兼容性，不能由配置测试保证。本轮不改变已接受的共享 custom 策略或备份格式。
