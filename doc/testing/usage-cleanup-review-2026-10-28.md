# 用量统计复核与文件清理 .89

日期：2026-10-28（America/Los_Angeles）。在 .88 用量改进和用户 .86 Antigravity 修复基础上完成。

## 上游对比与统计口径

沿用已核实的固定提交：[CC Switch `6d6b7162`](https://github.com/farion1231/cc-switch/commit/6d6b7162f122ac0ce1356a14688c8c4f712db3c8)、[CLIProxyAPI `9717e325`](https://github.com/router-for-me/CLIProxyAPI/commit/9717e325ba6ab2c7483ea93ccb5f2047eb2e7dd5)。具体证据见 [上游比较](usage-overview-comparison-2026-10-28.md) 和 [.88 实现](usage-overview-implementation-2026-10-28.md)。本次优化保存、核对和统计质量，未全量升级 sidecar。

原有包含式口径保持不变：总量为输入加输出，缓存读写是输入子集，推理是输出子集，不再额外相加；未知缓存不进入命中率分母，Credits 和官方额度百分比保持独立。独立复核对 7,800 组有效计数比较了这些规则，未发现正常计数口径变化。子代理用途分类不增加总量。

本轮补齐：

- 向旧版导出的 JSON 按原有五维键合并账号和任务拆分，避免旧版读取同键记录时覆盖一半用量。
- 保存已确认的兼容导出基线；降级旧版新增的可证明单调增量在升级后只导入一次，不猜测其账号或任务归属。首次旧账本导入和基线在同一事务提交。
- 无基线、未确认导出或不安全变化进入待核对备份并告警；无法保留原文件时阻止覆盖。缺失或损坏的兼容 JSON 不阻断事实库启动。
- 本机补计候选先检查原始缓存与总量的矛盾，避免先截断再把冲突数据误判为完整。

没有修改 provider 路由、子代理派发、压缩、上下文加解密或登录配置；没有调用真实模型或改写生产账本。

## 文件清理

新增独立的产物证据、生成目录识别和运行进程路径模块，扫描/人工选择/执行沿用原有边界。

- 读取应用 Info.plist 中的 bundle ID、版本与构建号，提示同应用存在更高版本。版本较早只是线索，不自动判断过时或可删。
- 安装包名称版本与内容相同证据分别展示。内容比较只针对同系列、同大小候选，SHA-256 读取有单文件 64 MiB、合计 256 MiB 预算；超限明确提示。普通源码、文档、提示词不参与比较。
- 识别本地 release/dist/out/build 等目录中的应用、安装包、TokenFlow 隐藏安装备份；有项目及工具标记的 Playwright 报告、测试结果和覆盖率产物；Python、pytest/mypy/Ruff/Vite、Electron 构建缓存。
- 新应用、重复包和测试报告默认不选中。已知运行中的应用禁用清理；执行时先查询进程，再校验文件指纹和规范路径，最后调用原有废纸篓/单独确认的永久删除入口。
- 通用 tmp/output/screenshots、版本化源码文档、模型权重、Git 工作树和会话不会仅凭名称或时间被认定为垃圾。

边界和用户操作见 [文件清理指南](../guides/file-cleanup.md)。本次没有清理任何真实用户文件。

## Standards review

发现清理前二次进程查询位于最终文件验证之后，会扩大可替换路径的窗口。现已调整为进程查询 → 完整指纹验证 → 规范路径验证 → 执行，并以查询期间替换应用目录的隔离测试验证拒绝清理。没有声称按路径删除具备系统级原子性。

补齐证据字段、运行应用独立禁选、有限内容读取和指南。复核者独立运行相关 6 项测试通过，确认上述 P1 闭合、无剩余阻塞问题。进程访问权限、AppImage 挂载和解释器任务仍可能导致运行状态覆盖不完整；大量应用版本比较的性能可后续优化。
