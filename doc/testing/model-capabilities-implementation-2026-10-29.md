# 模型能力缓存与推理档位适配

日期：2026-10-29（America/Los_Angeles）。本次只更新源码及构建产物，未替换安装应用或 4180 下载包，未修改真实 Codex 配置、登录或对话。

## 数据与转换边界

- `model-capabilities.ts`：白名单读取上下文、输入/输出上限、压缩阈值、有效比例、模态及原生推理声明。总窗口、最大输入、最大输出分开；不保存响应中的凭据、headers 或任意额外字段。
- `model-metadata-cache.ts`：持久化可重建的能力快照，记录作用域及获取时间。API 按来源、凭据引用版本、实际 URL、协议、模型隔离；账号按账号 ID、provider、已导入授权文件的摘要和模型隔离。一般能力缓存期限 7 天。缓存损坏按缺失处理，不能为账号增加可调用模型。
- 账号仍先获取可用模型清单，再复用该身份的能力快照。sidecar 的登记能力可能包含经过维护的静态模型表，不把全部 thinking 字段误称为本次网络返回。实时 `supported_reasoning_levels`（包括空数组）覆盖登记预设。
- `model-presets.ts`：固定 CC Switch `b76426741ef93069e2f374ac01ca7ef5760e1d0e` 的五类来源预设；DeepSeek 另外核对官方 Codex 文档。精确匹配端点、协议及模型 ID，未知别名不克隆旗舰能力。实时字段优先于预设；未知模型保留保守调度预算。预设声明不是实测证据或账号权限。
- API `/models` 读取不再丢弃已声明的能力字段。更换来源、Key、URL 或协议后不会沿用不匹配的缓存。读取和更新只接在已有导入/刷新/应用流程中，不新增启动时读取未导入本机授权的行为。

## Codex 目录及官方缓存

- 生成目录时按所选账号/来源取得能力，而非同名模型的第一个账号。网关的摘要规划也读取相同的来源窗口。
- 供应商原始能力与生成目录分开。统一网关的 v1 子代理覆盖留在适配层；官方原始模型字段保持原样，沿用已有统一网关 v1 规则。
- 新生成目录携带来源映射及能力快照；已有的全局窗口刷新器不再部分改写具有能力快照的目录。用户再次应用接入时整体生成新目录，避免“模型目录更新、子代理说明还是旧档位”不一致。更新缓存不等于运行中的 Codex 热加载完成。
- `model_catalog_json` 仍只是本机目录路径。官方账号完整目录另缓存于配置目录下 `.tokenflow-cache/model-metadata`，按账号/授权摘要、端点和 Codex 版本隔离；默认新鲜期 6 小时，遵守更短的 `max-age`、`no-store`、`no-cache` 和 `must-revalidate`，支持 ETag/304。允许时网络失败复用 24 小时内的同身份快照；拒绝认证时清除该快照。
- 官方账号切换/恢复及旧 hybrid 模式重新应用仍强制验证候选账号，不能以缓存跳过身份切换的前置检查。统一网关同身份应用可以复用新鲜目录。

## 推理档位

- 原生 effort 字符串原样传递。DeepSeek 的 `max` 不改为 `xhigh`；默认 `high` 来自官方目录。官方 DeepSeek 上下文采用声明的 1,048,576，压缩阈值保持 null，由 Codex 默认规则决定，不再固定 32K。
- 未声明推理能力的模型不再虚构一个 `medium` 选项。没有声明默认值时不伪造供应商默认。
- 预算型模型仅在实际经过 Claude/Gemini/Antigravity 对应转换器的账号路由中编译为 Codex 档位。预算值遵循 CLIProxyAPI 现有映射，仅公布在原生预算范围及已知输出上限内的值。它是转换器调度政策，不代表跨供应商推理能力等价；实际请求转换继续由 Go 层负责。
- API 直连及未验证的 API 预算路由不使用上述换算。声明原生 effort 的 API 则直接提供这些档位。
- 硅基流动指定 DeepSeek Chat 预设需要 `enable_thinking` 开关；网关在其已声明 effort 被选中时补充开关，保留明确传入的开关及 effort 字符串。其他端点/同名模型不套用这条映射。
- 预设涉及的 Kimi、智谱、MiniMax、硅基流动未在本次进行真实上游请求；其字段是有固定来源的预设回退。
