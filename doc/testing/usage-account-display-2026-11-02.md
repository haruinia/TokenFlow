# 同账号用量统一展示（.106）

## 修复范围

原来共存入口按请求认证的 `billingAccountHash` 分组，已保存账号的渠道按 `sourceId` 分组，同一账号在页面出现两项。读取用量总览时，现在用已验证的账号 ID 关联显示用的来源 ID 与账号名称。现有凭据池已经确认的重复授权／旧来源别名也关联到当前账号。

只增加读时展示元数据；原来的 `sourceId`、认证 hash、响应 ID、父/子代理分类、Token、失败数和计量状态不改写。原始账本 API、持久化与去重逻辑不变。页面同账号只显示一项，已有「用量详情」继续分别显示「经 TokenFlow」「本机日志」。不把本机日志来源误称为已验证的网络直连。

关联使用提供商与认证账号 ID，不仅凭邮箱或当前登录推断历史身份。共享 workspace 存在多个登录身份、或证据冲突时保留原来的未关联项。没有保存的来源时，可用唯一的已验证历史账号名称显示，不伪造关联。

复用统计扫描已有的账号元数据和凭据池别名，不新增钥匙串读取或上游探测。关联目录只含 hash、来源 ID 和名称，不向页面发送原始认证账号 ID 或令牌。

## 验证

- 展示回归覆盖官方共存、账号池与本机日志合并、子代理标记保留、渠道详情、旧授权别名、同邮箱不同账号不合并、共享 workspace 歧义、API 隔离与历史名称回退。
- 服务边界验证总览带展示别名、原始账本 API 不带别名，原字段与合计保持不变。
- 生产数据只读回放：目标账号在保留的请求事实中有 16,614 条记录，从两项合并为一项，全部原字段逐项相同；持久化日汇总的旧授权来源同样从两项合为一项。此数量是验证时保留的全量，不是用户截图选定时间范围的新统计结果。
- 未修改生产账本、会话、登录或供应商配置；没有发送模型请求。
