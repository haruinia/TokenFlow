# Codex 双入口子代理产品接入（10.15.26.70）

用户选择双入口：官方父代理派发官方子代理保留原入口；派发网关子代理使用可读任务入口，复用同一套原生任务管理。此前的双入口及 Code Mode 实验保存在 `52eb660`、`947c7d9` 及对应测试文档。本次接入 TokenFlow 的配置、启动、备份和界面状态，不覆盖官方 Codex 程序。

## 使用和备份

TokenFlow 自动管理所需文件。应用“官方账号＋网关模型”时，先验证独立兼容引擎及官方 CLI 版本，再沿用现有 `agent-backups` 记录机制保存修改前配置。修改启动桥或路由文件前，保存 `codex-direct-bridge/backups/*.json` 快照；相同启动配置重复应用不新增快照。版本化引擎复制到 `codex-direct-bridge/engines/<revision>/`，旧版本不覆盖。

首次从 TokenFlow 重启 Codex 后加载双入口。普通应用图标启动不保证加载桥，界面区分配置支持和当前进程已加载。官方推理与压缩仍使用 `openai` provider 直接访问官方；网关模型使用 `token_flow`。退出 TokenFlow 不关闭独立引擎，但网关推理仍需要 TokenFlow 服务在线。配置与启动参数由 TokenFlow 管理，用户无需手动修改 Codex 设置或为每次派发切换设置。

官方父代理发给网关的任务使用 `tokenflow_agents.spawn_agent/followup_task/send_message`。官方子代理保留 `collaboration` 原入口。网关父代理可以使用原入口派发网关子代理。两个入口复用原生 AgentControl、父子关系、权限、状态、失败通知、等待与取消。跨 provider 使用新任务及显式说明，暂不允许完整历史 fork；官方不透明上下文不可直接交给第三方。

## 版本与故障保护

源代码固定在 OpenAI Codex `970111f6cb62cc02fe36a82ea7d71b37a2889c97`，验证的官方 CLI 是 `codex-cli 0.164.0-alpha.11.1`。补丁、构建脚本和许可均入库；生成二进制在忽略目录中单独打包。启动前检查平台、架构、SHA-256 和官方 CLI 精确版本。版本检查也在任何请求关闭 Codex 前执行。版本不匹配时提示升级 TokenFlow 或恢复官方直连，不静默使用未经验证的组合。

每次派发读取当前路由文件；添加已配置网关模型无需替换引擎。未知/歧义模型、缺失 provider、跨 provider 全历史 fork、误把官方加密任务发给网关均在子代理推理前拒绝。原官方加密消息 schema 保留，别名仅去掉任务消息的 encrypted 标记。权限过滤先检查原工具，再检查别名工具。
