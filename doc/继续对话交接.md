## 产品要求

某个 Agent 的任务做不完时，把对话记录交给另一个 Agent，在同一个工作区接着做。

- 用量总览、活动留在侧栏原位置。顺序是：用量总览、活动、工具箱、设置。
- 工具箱里只有两个功能：文件清理、继续对话。
- 继续对话是工具箱里的独立页面，不是每个 Agent 面板上的按钮。
- 现在可以互转的只有：Codex、Claude Code、WorkBuddy、WorkBuddyAI、Qoder、Pi、DeepSeek Harness。
- Cursor、Antigravity、Qoder IDE 不在范围内。它们的存储不适合写入。
- 不复制项目目录。目标 Agent 继续使用原来的工作区绝对路径。
- 不删除原来的对话。
- 不复制系统提示、开发者指令、base instructions、thinking。
- 新对话标题以「继续：」开头。用户重新打开目标 Agent 后，找这个标题。
- 文件清理的维修上下文保持 `{page:'cleanup', intent:'file-cleanup'}`。不要为了工具箱去改维修页的 `cleanup` 枚举。

## 已经做完的行为

界面：

- `main.tsx` 的次级导航是用量总览、活动、工具箱、设置。工具箱图标用 `briefcase`。
- 工具箱内部用「文件清理 / 继续对话」切换。文件清理仍是原来的 `FileCleanupPane`。
- 继续对话页可以选择来源 Agent、一条对话、另一个目标 Agent，然后提交。
- 成功提示说明工作区没变，并要求打开标题以「继续：」开头的对话。

程序：

- `ConversationHandoff` 负责列出和写入各 Agent 的原生会话文件。
- 浏览器端类型放在 `conversation-handoff-shared.ts`，这个文件不能引入 Node，否则 Vite 会把 `fs` 打进控制台。
- `GET /api/a2a/conversations?agent=` 只返回元数据，不返回正文。`agent` 可省略。
- `POST /api/a2a/handoff` 的请求体是 `{source, id, target}`。它在变更锁里，需要本机管理员 cookie 或 bearer。
- 同一来源和目标会被拒绝，提示选择另一个 Agent。
- 会话 id 不能含 `..`，符号链接会被拒绝。
- 工作区必须是已经存在的真实目录。
- 列表每份文件只顺序扫描开头 1MB，扫过就丢掉，并在文件更大时标记 `partial`。转交流式读完整份文件，不把正文收成一个字符串。内存里只保留截断后的副本：最多 80 条、共 6 万字、单条 6000 字。留下第一条用户消息和最近的消息。单行超过 256KB 会跳过并记为截断。保留下来的标题和正文都先复制成独立字符串，避免 V8 的子字符串把整份会话留在堆上（`claude-code-desktop` 上 Codex 切换溢出就是这个原因）。
- DeepSeek 按压缩帧流式解压，解压块随读随弃，不再把所有帧拼成一份全文。单个压缩块超过 8MB 则拒绝该文件。写入仍用一整帧。
- 每个来源最多列出最新 40 条。扫描深度 6，跳过符号链接、`memory`、`node_modules`，最多看 8000 个文件。
- 追加给目标的用户消息会写明来源 Agent、绝对工作区，并说明任务还没完成、不要重做已完成的部分。
- Codex 桌面索引是尽力写入已有的 `state_5.sqlite`。数据库不存在、是符号链接或小于 100 字节时不创建新库，结果注明「Codex 会话索引未能更新。」JSONL 仍然保存。
- 交接流水写在 TokenFlow 数据根目录的 `conversation-handoffs.json`，只存元数据，权限 `0600`，最多 50 条。写失败时对话文件仍算已保存。
